# 基于Spark的北京市医疗机构资源整合与多维筛选可视化系统

大数据工程技术毕业设计。以公开机构资料治理、Spark专题加工和可核验的数据分析为主线，提供机构查询、找医生、数据总览、医疗资源分析、智能问答，以及统一的帮助与数据说明入口。

## 使用与分析

- 机构查询支持组合条件、明确查询范围、来源、详情、收藏对比和导出。
- 医生查询支持医院、科室、姓名与行政区联动，保留官方出处和核验日期。预约统一前往北京114；本系统不掌握实时号源，不接收挂号订单。
- 数据总览呈现规模、分区地图与类型构成。地图默认分区色块，机构散点按需开启。
- 医疗资源分析只有一组五类专题：区域资源结构、基层服务结构、科室与专科、协作网络覆盖、数据治理成效。相关详细图表直接纳入专题。条形图用于数量排名，环形图用于办别与坐标构成，柱状图用于专科分档及分组比较，热力矩阵用于交叉关系。提供分析依据、统计限制、下钻与CSV。
- 智能问答先运行本地解析与真实查询，再按可用状态请求智能说明；支持继续提问与失败降级。来源缺失不解释为没有服务。问答仅涉及机构资源，不提供诊断或用药建议。

## 技术实现

Python负责本地异构资料读取和治理。HDFS保存入湖数据和分层结果，PySpark 3.5.3组织ODS、DWD、DWS、ADS加工，MySQL 8保存应用结果。Flask提供接口。当前运行前端使用HTML、CSS、原生JavaScript与ECharts，Vue源码仅作历史实现保留，旧 `/spa/` 跳转当前入口。

研究专题从冻结ADS快照在Spark `local[2]`重算，新增5张专题结果表及独立HDFS输出。本轮未重跑上游ODS/DWD。16区六维特征执行k=2至5、种子7和42共8组KMeans，存在种子敏感性。万级记录和单机实验不能证明大规模分布式性能。

## 运行

直接打开 `web/dashboard_offline.html` 可使用内嵌快照和本地查询，无须数据库。网络模型说明、官网与114需要网络，浏览器定位通常需要HTTP。

```bash
python3 -m pip install -r requirements.txt
python3 web/app.py
# 浏览器访问 http://127.0.0.1:5001
```

完整数据工程运行步骤见[系统运行流程](docs/系统运行流程.md)和 `scripts/run_pipeline.sh`。原始文件、处理数据和密钥按现有规则在本地留存，克隆仓库不等于取得原始数据或复现全部ETL。离线成品可直接查看；源码重建需要本地快照、依赖和相应数据库环境。

```bash
# 仅重建前端，复用已有本地快照
PYTHON_BIN=python3 bash web/build_spa.sh --no-db
# 同批次研究专题
bash spark/run_research.sh
# 当前回归，Node为运行时可执行文件
python3 scripts/validate_current.py --node /path/to/node --base-url http://127.0.0.1:5001
```

固定单查询索引实验预热5次、采样30次、并发1，有索引中位数0.481ms、p95 0.851ms，忽略二级索引后为8.731ms、32.047ms。这不包含浏览器、HTTP、模型与生产并发。

真实用户试用尚未完成，记录表留在 `docs/分析深化与用户验证/`。历史隔离部署证据不视为当前上游全链路复验。缺少人口、床位和就诊量，不判断资源充足性、医疗质量或实际交通可达性。

## 文件入口

- `web/`：当前前端、Flask、离线成品与字典。
- `etl/`：治理、指标导出、医生导入与批次核对。
- `spark/`：分层及专题作业。
- `tests/`、`scripts/`：回归与运行入口。
- `docs/`：指标、验证、工程记录与使用说明。
- `论文/`：本地最终论文、开题报告和学校模板参考。
- `答辩材料/`：本地两套最终PPT及逐页演讲稿。

学位材料、密钥、原始资料和历史备份遵循现有排除规则，不随代码推送。整理说明和当前材料清单见 `docs/收尾同步说明-20261021.md`。
