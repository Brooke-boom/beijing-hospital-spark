# 系统回溯评价与改进建议

评审日期：2026-10-21。对象：当前桌面毕业设计项目，页面版本v6.17及后续布局调整。本轮为复核与建议，未修改业务代码或数据。

## 总体判断

作为大数据工程技术专业毕业设计，项目已有较完整的工程链路和可演示成果：多源公开资料、清洗治理、HDFS分层、Spark专题计算、MySQL服务、可视化查询、来源追溯。当前更适合定位为“医疗机构公开资源整合与分析系统”。公开上线所需的数据持续维护、信任边界与运行管理仍未闭环。

9,678条机构记录足以支撑本项目功能与工程验证，但不能仅凭技术栈证明大规模分布式处理性能。分析可以描述收录结构与分布，不宜证明医疗质量、服务能力或资源是否充足。

## 本轮证据

- 当前指标表：机构9,678；三级记录180；高精度坐标3,865（39.94%）；有科室映射6,745（69.69%），有来源记录772（7.98%）；重点专科名单名称覆盖90条机构记录。
- 医生资料309条，关联15个医院ID，考虑医院级院区关联后20/180条目标机构有部分资料，160条待补录；不等于20家全院名录已完整。
- 研究验证记录保留5张Spark专题结果和24项一致性检查；部署记录存在独立Python依赖、全新MySQL卷、首页/API/重启持久化7项检查，但范围明确不含上游ETL全链重建。本轮未重新执行该部署实验。
- 真实用户试用CSV25条任务记录均为pending；模拟试用与自动化不能代替真人实测。
- 本轮执行10个JavaScript测试入口：8个通过，2个失败。test_chat_workflows.js仍期待等待智能说明期间禁用发送；test_direction_analysis.js的隔离环境缺setText，且仍验证旧折叠入口懒初始化。须按新需求更新测试，并验证新交互，不能仅删除断言。
- 离线构建约11.72MiB；未据此认定慢，需测首屏、筛选与图表绘制耗时。

## 优先改进

### P0：统一指标谓词和发布验证

新发现：总览社区机构为1,445，基层专题为1,455。总览renderOverviewKPI按名称正则匹配，专题directionRows按机构类别统计。快照类别中社区卫生服务中心250、社区卫生服务站1,205，合计1,455。并非同一指标同一算法；应以标准类别确定主口径，名称规则仅用于异常核对，统一网页、导出和论文引用。

统一指标注册表至少包含：指标名、计算字段、筛选谓词、分母、批次、适用范围与限制。增加跨页面相等断言，避免逐个修补数字。

修复两项旧测试，建立一个统一发布入口，报告全部测试结果、代码版本、快照指纹和构建产物。专项通过与全套通过分开表述。

### P1：把分析贡献讲深

保留现有专题，重点完成三条叙述：三级机构区域分布；科室来源覆盖与采集偏差；协作网络交集与去重。每条固定展示问题、输入字段、Spark处理、图表、数值结论、限制和导出依据。缺少人口/床位/服务量时避免“资源密度、可及性、供给充足”等超出数据能力的名称。

### P1：明确并维护数据覆盖

医生优先完成少量医院的可核实名录，再逐步扩大覆盖，医院级关联不得等同院区出诊。建立新增/变更/失效来源、最近核验、下一次复查和待人工确认状态。科室记录保持“有来源”与“规则映射”区分；粗精度坐标不参与精确半径判断。

### P1：补真实用户试用与当前版本验证

按现有任务安排3—5位未参与开发者，记录无辅助成功率、耗时、误操作、需要帮助次数及原话；修复后复测，保留版本号。对最终发布版重做隔离恢复部署，再安排从冻结输入经上游ETL、数仓到网页的完整重建实验，记录每层行数、耗时及校验值。

### P1：上线前加强事实与管理边界

/api/ai/chat当前接收浏览器提交的facts，再交给模型；不能仅凭该链路保证服务端事实可信。线上应由后端根据条件重新查询，绑定快照/查询标识，结构化结果固定显示，生成说明补充呈现并校验关键数值。

/api/admin/stats在所检查处理函数中未见身份校验；埋点可写入。公开部署前应核对全局访问控制，限制管理端及写入/模型请求，补运行日志与健康检查。未进行全面安全审计，不将这些观察表述为已确认可利用漏洞。

### P2：停止堆叠样式，统一前端规则

近期页面主线已明显清晰，继续按用户任务收敛。统一标题、筛选条、结果列表、图表、展开说明、空状态、加载与错误组件；一次只突出主要动作。整合后的每专题建议2—3幅主图，其余明确标为可深入查看，避免重新形成长图表清单。

app.js约4,439行，HTML与多轮CSS覆盖仍有维护负担。先按查询、分析、详情、状态拆模块，保留同源在线/离线构建；不必为技术栈展示同时维护两套前端。

## 文档同步

README仍以“AI主线、4个支撑页、悬浮窗口”描述系统；当前版本验证结果顶部仍为v6.12。统一为当前架构与实际能力，明确Vue源码保留与当前运行实现的区别。论文/PPT引用当前指标表，不把历史验证与当前版本混写。

## 建议验收顺序

1. 修正社区机构定义与旧测试，发布报告可一次复现。
2. 完成三条分析证据链和真实用户试用。
3. 冻结数据/代码，重做当前版本部署及完整链路验证。
4. 最后统一论文、PPT、截图和演讲备注；此后仅修复阻断问题。
