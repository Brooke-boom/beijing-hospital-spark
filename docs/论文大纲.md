## 第 3 章 系统需求分析与总体设计 ✅（架构已定型，可写初稿）

- 3.1 需求分析
  - 功能性需求：多维筛选（区域/等级/类型/科室/距离）、多策略排序（距离/等级/负载/加权评分）、机构详情页、可视化大屏
  - 非功能性需求：查询性能（MySQL ADS 层支撑）、可移植性（Docker Compose 一键部署）、可扩展性
- 3.2 系统总体架构
  - 数据流：多源 CSV/XLSX → Spark ETL → 分层数仓 → MySQL ADS → Flask API → ECharts 前端
  - 部署架构：spark-master / spark-worker / mysql 三容器编排
- 3.3 数据仓库分层设计
  - ODS（原始登记数据）→ DWD（清洗标准化主表 + 科室字典 + 坐标）→ DWS（区县/等级/类型粒度汇总 + 负载指标）→ ADS（筛选排序服务表）
- 3.4 数据库设计（主表 17 字段、医院-科室映射、坐标缓存表结构）
- 3.5 接口设计（筛选 / 排序 / 详情 / 统计 API 规范）
