# 系统运行流程（从零到跑起来）

> 本文说明本项目的**四种运行方式**，按"从简到全"排列。所有命令与输出均为 2026-09-10 在本机（Mac M1 / macOS）实测。  
> 只想看效果 → 用方式一（30 秒）；要答辩演示 → 方式一 + 方式二；要体现完整工程链路 → 方式三。

---

## 零、先理解：系统由哪几段组成

```
① 数据层   data/processed/master_institutions.csv   ← 9,789 家 × 32 列（数据中枢）
② 计算层   spark/etl_hospital.py                    ← Spark 四层 ETL，产出写 MySQL
③ 存储层   MySQL ads_inst_search（3307 端口，40 列） ← Flask 直接查
④ 服务层   web/app.py（Flask，默认 5001 端口）       ← 11 个 API
⑤ 展现层   web/dashboard_offline.html                ← 零依赖单文件大屏（6.5MB）
```

**关键认知**：⑤ 已经把数据内联进 HTML，所以它**不依赖 ②③④**，双击就能看。  
②③④ 是"数据可更新、接口可调用"的完整工程链路，答辩时用来体现技术深度。

## 方式一：离线大屏（零依赖，30 秒）

**适用**：给老师/面试官演示、快速查看效果、网络环境差。

```bash
# 直接打开（任选一种）
open web/dashboard_offline.html                      # macOS
# 或双击该文件
```

- 无需 Python、无需 Docker、无需数据库、无需联网
- 支持：七维筛选、四种排序、图表联动、详情弹窗、自然语言查询
- **不支持**：数据实时更新（是构建时的快照）

> ⚠️ 定位功能在 `file://` 协议下浏览器会拒绝授权。需要测定位请用方式二走 `http://`。

---

## 方式二：启动 Web 服务（Flask + MySQL，推荐答辩用）

**前置条件**：MySQL 在 3307 端口已有数据（本项目由 Docker 容器提供）。

```bash
# 1. 确认数据库在（应返回 9,789）
docker ps --format '{{.Names}}\t{{.Status}}' | grep mysql

# 2. 启动服务
bash web/start.sh                    # 默认 5001 端口
# 换端口：PORT=8000 bash web/start.sh

# 3. 浏览器打开
open http://localhost:5001
```

**实测验证**（三条命令确认真的跑起来了）：

```bash
curl -s http://127.0.0.1:5001/api/health
# -> {"institutions":9789,"status":"ok"}

curl -s "http://127.0.0.1:5001/api/institutions?district=海淀区&level=三级&page_size=2"

curl -s -o /dev/null -w "status=%{http_code}\n" http://127.0.0.1:5001/
# -> status=200
```

**停止服务**：`Ctrl+C`（若后台运行则 `pkill -f "web/app.py"`）

> 💡 若 MySQL 未启动，脚本会警告但**仍会启动 Flask**，此时接口会报数据库连接错误。看到警告先 `docker compose up -d mysql`。

## 方式三：Docker Compose 全栈（完整工程链路）

**适用**：从零重建、演示"数据处理→存储→服务"全过程、写进简历的部署实践。

```bash
# 1. 启动 Spark 集群 + MySQL（首次会拉镜像，约几分钟）
docker compose up -d

# 2. 确认容器状态
docker compose ps          # 应见 spark-master / spark-worker / hospital-mysql 三个 Up

# 3. 提交 Spark ETL（CSV → ODS → DWD → DWS → ADS → MySQL）
docker exec spark-master /opt/spark/bin/spark-submit \
  --master spark://spark-master:7077 \
  --jars /opt/workspace/jobs/mysql-connector-j-8.4.0.jar \
  --driver-class-path /opt/workspace/jobs/mysql-connector-j-8.4.0.jar \
  /opt/workspace/jobs/etl_hospital.py

# 4. 【必做】重建查询索引（ETL 的 overwrite 模式会 DROP+CREATE 表，索引会全丢）
python etl/create_indexes.py

# 4.5 加载智能导诊知识库维度（首跑或更新疾病词典后执行）
python etl/build_disease_dept_map.py     # 生成 data/processed/disease_dept_map.csv（262 条 / 29 科室）
python etl/load_disease_dept.py          # 写入 MySQL 维度表 dim_disease_dept（供 /api/triage 使用）

# 5. 【必做】重新生成快照与离线大屏
bash web/build_spa.sh

# 6. 启动 Web 服务
bash web/start.sh
```

**可视化管理界面**：

- Spark Master UI：<http://localhost:8080>
- Spark Worker UI：<http://localhost:8081>

## 方式四：数据更新链路（源数据变了怎么走）

用于"我改了源 CSV / 新增了治理字段"的场景，按顺序执行：

```bash
# ① 离线治理（办别 / 子类 / 擅长分级等）→ 更新 master_institutions.csv
python etl/govern_master.py

# ② 整合协作网络维度（net_* 字段）→ 主表 / wide 表 / MySQL 三层同步
python etl/integrate_networks.py

# ③ 机构更名同步（如有）
python etl/fix_renamed_institutions.py

# ④ Spark 四层 ETL → MySQL
docker exec spark-master /opt/spark/bin/spark-submit ... /opt/workspace/jobs/etl_hospital.py

# ⑤ 重建索引（④ 之后必做）
python etl/create_indexes.py

# ⑤.5 智能导诊知识库（若 build_disease_dept_map.py 调整过）
python etl/build_disease_dept_map.py && python etl/load_disease_dept.py

# ⑥ 重建快照与离线大屏
bash web/build_spa.sh

# ⑦ 提交（web 产物入库）
git add web/dashboard_offline.html web/templates/index.html && git commit -m "..."
```

> 📌 步骤 ④⑤⑥ 顺序不能乱：先 ETL 写库 → 再建索引 → 再从库抽快照。

## 常见问题（实测踩过的坑）

| 现象                                | 原因                                     | 解决                                                     |
| --------------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 端口 5000 起不来                       | macOS AirPlay Receiver 占用 5000         | 用默认 5001，或 `PORT=8000 bash web/start.sh`               |
| MySQL 连不上                         | 容器未启动，或 3306 被本机 MySQL 占用              | 容器映射到 **3307**；`docker compose up -d mysql`            |
| `docker: command not found`       | Docker Desktop 已装但 CLI 不在当前 PATH（沙盒常见） | 用 `/usr/local/bin/docker`，或把 `/usr/local/bin` 加入 PATH  |
| Flask 起来了但接口报错                    | MySQL 无数据（没跑过 ETL）                     | 走方式三第 3 步；`/api/health` 应返回 9789                       |
| 查询变慢                              | ETL 后索引被清掉了                            | 重跑 `python etl/create_indexes.py`                      |
| 建索引报 error 1170                   | Spark 建表字符串列是 TEXT，MySQL 禁直接建索引        | 脚本已用前缀索引，勿手工改                                          |
| 定位功能不弹授权                          | `file://` 协议被浏览器拒绝                     | 用方式二走 `http://localhost:5001`                          |
| 换台机器跑 `build_spa.sh` 报 python 不存在 | 脚本硬编码了本机 Python 绝对路径                   | 把 `/Users/brooke/.workbuddy/.../python` 换成你的 `python3` |
| 大屏数据还是旧的                          | 浏览器缓存                                  | `Cmd + Shift + R` 硬刷新                                  |

## 环境与依赖

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt     # flask + pymysql + requests
```

- Docker Desktop（Spark + MySQL 容器）
- Spark 3.5.3 / MySQL 8.0 均由容器提供，**宿主机无需单独安装**
- 离线大屏无需任何依赖
