# 开发日志

> 项目：基于 Spark 的北京市医院医疗资源整合与智能筛选可视化系统

> 命名约定：P0=阻塞性问题，P1=功能问题，P2=优化项。

- 确定毕设题目并完成关键定位调整：从"智能推荐"改为 **"资源整合 + 多维筛选 + 排序 + 详情页"** 路线。

### 关键决策记录
| 决策点 | 结论 | 理由 |
|---|---|---|
| 计算引擎 | Spark 3.5.3（PySpark） | 满足毕设"大数据"定位；官方镜像原生支持 arm64 |
| 存储 | HDFS/Hive（过程层）+ MySQL 8.0（ADS 结果层） | 分层存储，ADS 供 Flask 低延迟查询 |

### 核心清洗逻辑
- **去重合并**：规范化机构名（去空格/统一括号/去"北京市"前缀）作为归并键；按字段丰富度择优合并；`src_count` 记录多源交叉验证次数。原始 13,803 条 → 9,791 家。
- **等级编码统一**：三种体系（数字码"5"、中文"一级无等"、"三级+未评"）→ 统一为"一/二/三级 + 甲/乙等次"。
- **区名清洗**："北京昌平区"等脏值 → 标准区名，仅 42 家（0.4%）无法识别区。
