# 开发日志

> 项目：基于 Spark 的北京市医院医疗资源整合与智能筛选可视化系统
> 说明：本日志按时间线记录开发过程、遇到的问题与解决方案，是论文第 4/5 章的素材库。
> 命名约定：P0=阻塞性问题，P1=功能问题，P2=优化项。

---

## 2026-09-02（第 1 天）：选题定调与数据获取

### 完成事项
- 确定毕设题目并完成关键定位调整：从"智能推荐"改为 **"资源整合 + 多维筛选 + 排序 + 详情页"** 路线。
  - 筛选维度：区域 / 等级 / 类型 / 科室 / Haversine 距离
  - 排序方式：距离 / 等级 / 负载 / 加权评分
  - 放弃协同过滤推荐（本科阶段数据不足以支撑可信推荐，且与"资源整合"主线不符）
- 以学校模板生成开题报告（docx），并清空指导教师意见栏等待老师填写。
- 确定技术栈与部署路线：GitHub 公开仓库 + Docker Compose 本地部署 + 项目文档，不做完整集群上云。

### 关键决策记录
| 决策点 | 结论 | 理由 |
|---|---|---|
| 计算引擎 | Spark 3.5.3（PySpark） | 满足毕设"大数据"定位；官方镜像原生支持 arm64 |
| 存储 | HDFS/Hive（过程层）+ MySQL 8.0（ADS 结果层） | 分层存储，ADS 供 Flask 低延迟查询 |
| 展示 | Flask + ECharts | 轻量、生态成熟、简历认可度高 |
| 运行环境 | Mac M1 + Docker Desktop | apache/spark 官方镜像原生支持 linux/arm64，无需 x86 转译 |

## 2026-09-02（晚）～ 09-03：数据清洗与主表构建

### 完成事项
- 编写 `etl/clean_merge.py`：70 个异构文件 → 统一机构主表。
- 产出 `data/processed/master_institutions.csv`：**9,791 家机构，17 字段**
  （id, name, district, category, level, level_sub, addr, phone, postal, beds, key_depts, traffic, website, econ, profit, category_raw, src_count, source_files）
- 产出 `specialty_departments.csv`（20 家三甲医院国家级重点专科）与 `data_quality_report.md`。

### 核心清洗逻辑
- **去重合并**：规范化机构名（去空格/统一括号/去"北京市"前缀）作为归并键；按字段丰富度择优合并；`src_count` 记录多源交叉验证次数。原始 13,803 条 → 9,791 家。
- **等级编码统一**：三种体系（数字码"5"、中文"一级无等"、"三级+未评"）→ 统一为"一/二/三级 + 甲/乙等次"。
- **区名清洗**："北京昌平区"等脏值 → 标准区名，仅 42 家（0.4%）无法识别区。

### 踩坑记录（论文素材）
| # | 问题（级别） | 现象 | 解决方案 |
|---|---|---|---|
| 1 | 通州某 xlsx 声明维度 1048542×16331（P0） | openpyxl 按声明维度加载直接 OOM | 限制 iter_rows 实际范围，逐行流式处理 |
| 2 | 3 个 xlsx 伪装成 .csv（P1） | pandas 读 CSV 报二进制错误 | 检测文件头，复制为 .xlsx 后缀后用 openpyxl 读 |
| 3 | 编码混杂（P1） | utf-8 / gbk / gb18030 交错 | 依次尝试 utf-8-sig → gbk → gb18030 的自适应解码链 |
| 4 | macOS NFC/NFD 文件名归一化（P1） | 同名文件 cp 覆盖失败 | 用 unicodedata.normalize('NFC') 做逻辑名对比 |
| 5 | iCloud"优化存储"上传数据文件（P0） | master_institutions.csv 消失，只剩 .icloud 占位文件 | 从工作区副本恢复；建议关闭桌面 iCloud 优化存储 |
| 6 | Excel 临时锁文件混入（P2） | `.~xxx.xlsx` 被当作数据文件 | 文件遍历时过滤 `~$` / `.~` 开头文件 |

### 数据质量现状（清洗后）
- district 完整率 99.6%、addr 89.5%、profit 85.1%
- level 仅 12%（原始数据登记率低）、phone 5.8%、beds 0.4% —— 决定后续用规则推导与模拟补齐

## 2026-09-03（上午）：地理编码

### 完成事项
- 申请高德开放平台 Web 服务 API Key（个人认证，免费额度 5,000 次/天）。
- 编写 `etl/geocode_amap.py`：批量地理编码，**断点续跑**设计（按机构 id 增量写入缓存，重跑自动跳过已编码）。
- 地址构造降级链路：详细地址 → 区 + 机构名 → 标记 failed 留待人工处理。
- 限流保护：QPS 间隔控制 + 日额度用尽自动停止。

### 进度
- 9-03 当日配额用尽自动停止，累计完成 **3,850 / 9,791（39.3%）**，结果存 `data/processed/geocode_cache.csv`。
- 剩余 5,941 条 > 单日 5,000 配额，需分两天跑完（预计 9-04、9-05 收尾）。

### 踩坑记录（论文素材）
| # | 问题（级别） | 现象 | 解决方案 |
|---|---|---|---|
| 7 | pandas 读 CSV 后 NaN 传入 str() 崩溃（P1） | 地理编码批量跑报 TypeError | `(rec.get("addr") or "").strip()` 防御性取值 |

| 9 | 地理编码精度分级（P2） | 部分坐标仅精确到"区县"级（行政区中心） | 保留高德返回的 level 字段，后续在坐标精度字段中标注，前端筛选排序时降权处理 |
