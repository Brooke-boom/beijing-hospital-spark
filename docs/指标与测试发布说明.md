# 指标统一与测试发布入口

指标定义的唯一源文件为web/metric_definitions.json。构建时由etl/export_project_metrics.py读取，按当前快照重算指标，将定义与数值一起写入project_metrics.json和snapshot_data.json；前端从内联快照读取同一份定义。definitions不改变原始机构字段，机构指纹保持不变。

本轮统一的指标包括：机构总数、医院类型记录、社区卫生服务机构、三级机构、坐标非空与精度、科室映射、有来源科室、专科名单名称覆盖。百分比随页面范围使用相应分母；总览固定全市，专题可以是筛选子集，不要求不同范围数值相等。

社区机构按category为社区卫生服务中心/社区卫生服务站，结果250+1205=1455条。废止总览按名称正则得到1445条的旧算法。医院类型681条、三级全部类型180条；“三级医院”必须另加医院类型条件。所有数量仍为机构记录，不能解释为去重医院实体或完整医生名录。

## 一次执行全部测试

先运行`bash web/build_spa.sh --no-db`，刷新同批次台账和在线/离线产物。

再执行：

```
python scripts/validate_current.py --node /path/to/node --base-url http://127.0.0.1:5001
```

解释器需安装项目测试依赖，Node须在PATH或通过--node指定。程序从任意工作目录启动均以项目根为基准，每个tests/test_*.js和tests/test_*.py在独立进程运行。缺失Node、断言失败、超时、指定HTTP不可达均记为失败，并返回非零退出码。未提供--base-url时HTTP明确记为未执行。

输出：docs/发布验证/current/验证报告.md、results.json和逐入口原始日志。结果绑定快照日期/指纹、解释器版本和源码及产物SHA256。测试文件数不是断言数，也不能当作用户数。

## 测试整理

- 两个问答测试共用tests/helpers/chat_fixture.js；工作流验证连续提问、乱序返回、清空后迟到回复及断网回退；口径测试验证23/28、限流、IME与拒答。
- 专题测试按实际集成结构验证无需折叠即初始化、仅当前专题可见、图表实例复用、事件仅绑定一次；不再断言已取消的旧折叠懒初始化。
- 新增test_metric_consistency.js，使用真实快照验证注册表/台账/总览/专题/Spark批次及筛选子集一致；增加名称和类别冲突、空集、零坐标等边界。

## 验证边界

此入口执行自动化测试与指定本地HTTP只读检查，不启动或重建容器，不重跑上游ETL，不执行模型调用、真人试用或生产部署。浏览器视觉观察、真人记录与隔离部署应另附日期和版本，不能因自动化通过改写为“已全部上线验收”。
