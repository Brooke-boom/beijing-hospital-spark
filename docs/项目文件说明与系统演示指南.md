## 三、数据流转关系

```
data/*.csv (70 原始源文件)
    ↓ etl/clean_merge.py + govern_master.py + 其他治理脚本
data/processed/master_institutions.csv (9,789 家 × 42 字段)
    ↓ etl/upload_to_hdfs.py（治理后 CSV + 行为日志入湖）
HDFS /hospital/ods/raw（原始文本，唯一权威副本）
    ↓ spark/jobs/（Spark 分层 + 维度作业）
HDFS /hospital/{ods/parquet, dwd, dws/{space,category,dept,network,time}, meta}
    ↓ layer_ads.py（服务层）
MySQL hospital 库（19 张表：DWD/DWS 服务副本 + ADS 结果 + 维度表）
    ↓                                        ↓
web/build_spa.sh                        Flask /api/*（22 个 JSON 路由）
    ↓                                        ↓
web/snapshot_data.json (6.25MB)         web/vue/ 构建产物（/spa/，前后端分离）
    ↓ 注入
web/dashboard_offline.html (7.49MB) ← 零依赖兜底 / GitHub Pages 可直接访问
```

展现层有**两种形态**，共用同一份 MySQL 数据：在线形态（Vue 3，走 `/api/*`）
与离线形态（单文件大屏，走内联快照）。二者互不依赖，任一种坏掉另一种仍可演示。

**改数据后的完整流程**（改一个就要全走一遍）：

```bash
# 1. 治理脚本（如改了 etl/）
python3 etl/xxx.py

# 2. 治理后数据重新入湖到 HDFS
python3 etl/upload_to_hdfs.py

# 3. 重跑数仓全链路（ODS → DWD → 五维分析 → ADS → MySQL）
bash spark/run_all.sh

# 4. 重建查询索引（overwrite 写表会清掉索引，必做）
python3 etl/create_indexes.py

# 5. 重建单文件快照与大屏（产出 3 份 HTML）
bash web/build_spa.sh

# 6. 改了 web/vue/src/ 才需要：重建 Vue 前端
bash web/vue/build.sh

# 7. 收尾校验：三份产物 + Vue 产物一致性
python3 etl/verify_artifacts.py

# 8. 提交
git add -A && git commit -m "..."
```

> 改动范围决定要跑几步：
> - 只改后端逻辑（不加路由）：全部跳过，重启 Flask 即可。
> - 只改 Vue 前端（`web/vue/src/`）：只跑第 6 步；不用重启 Flask（它托管的是静态文件）。
> - 改了数据或治理脚本：第 1–7 步全走。
