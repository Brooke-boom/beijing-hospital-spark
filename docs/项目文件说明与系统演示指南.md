## 三、数据流转关系

```
data/*.csv (70 原始)
    ↓ etl/clean_merge.py + govern_master.py + 其他 15 个治理脚本
data/processed/master_institutions.csv (9,789 家 × 28 字段)
    ↓ spark/etl_hospital.py（Docker 集群提交）
MySQL hospital 库（16 张表：ODS/DWD/DWS/ADS）
    ↓ web/build_spa.sh
web/snapshot_data.json (4.96MB)
    ↓ 注入
web/dashboard_offline.html (5.99MB) → GitHub 可点击
```

**改数据后的完整流程**（改一个就要全走一遍）：
```bash
# 1. 治理脚本（如改了 etl/）
python etl/xxx.py
# 2. 重跑 Spark ETL
docker exec spark-master /opt/spark/bin/spark-submit \
  --master spark://spark-master:7077 \
  --jars /opt/workspace/jobs/mysql-connector-j-8.4.0.jar \
  --driver-class-path /opt/workspace/jobs/mysql-connector-j-8.4.0.jar \
  /opt/workspace/jobs/etl_hospital.py
# 3. 重建前端快照与大屏
bash web/build_spa.sh
# 4. 提交（离线大屏是 GitHub 唯一可点击版本）
git add web/dashboard_offline.html web/templates/index.html && git commit -m "..."
```

## 四、系统演示步骤（答辩用）

### 4.1 演示前准备（3 步，约 2 分钟）

```bash
# ① 启动底层容器（MySQL + Spark 集群）
cd ~/Desktop/毕设 && docker compose up -d

# ② 启动 Flask 服务
bash web/start.sh        # 或：python web/app.py

# ③ 验证
curl http://127.0.0.1:5001/api/health
# 期望返回：{"institutions":9789, "status":"ok"}
```

**确认 3 个界面可达：**
| 界面 | 地址 | 用途 |
|---|---|---|
| 可视化大屏 | http://localhost:5001 | **主演示界面** |
| Spark Master | http://localhost:8080 | 展示集群与 22 次 ETL 记录 |
| MySQL | 127.0.0.1:3307（root/hospital123） | 展示 16 张分层表 |

⚠️ 必须用 `http://` 访问，不能用 `file://` 打开（定位功能会被浏览器拒绝授权）。

### 4.2 现场演示流程（8 步，约 5 分钟）

| 步骤 | 操作 | 口述要点 |
|---|---|---|
| **1. 总览** | 打开首页，看顶部统计卡 | "整合北京市 9,789 家医疗机构，其中三级 202 家、二级 223 家、一级 832 家" |
| **2. 区域筛选** | 选「朝阳区」 | 实时联动：列表 + 地图 + 等级分布饼图同步刷新 |
| **3. 等级筛选** | 叠加「三级」 | "多维条件是 AND 组合。注意饼图只统计 1,287 家应参评机构，这是口径治理的结果" |
| **4. 类型筛选** | 叠加「综合医院」 | 继续收窄，展示组合筛选能力 |
| **5. 距离筛选** | 切换基准点（如天安门→中关村），或点「定位」用当前位置 | "基于 Haversine 球面距离公式，按经纬度实时计算" |
| **6. 排序切换** | 依次点：综合评分 / 距离最近 / 等级优先 / 床位最多 / 科室最多 | "综合评分 = 等级 40% + 距离 30% + 科室 20% + 床位 10%，权重可解释" |
| **7. 详情浮层** | 点任一家医院 | 展示：重点专科（国家级/市级三层）、诊疗科室（L1/L2/L3）、床位、距离、坐标精度 |
| **8. 地图交互** | 缩放/框选地图 | 散点密度反映资源分布，可讲解"中心城区密集、郊区稀疏" |

**进阶演示（若老师追问数据真实性）**：
- 展示列表中的「**含推导**」标记 → 说明规则推导科室的可追溯设计
- 打开 http://localhost:8080 → 展示 22 次 ETL 全部 FINISHED
- 打开 MySQL → 展示 ODS/DWD/DWS/ADS 四层 16 张表

### 4.3 备用方案（现场网络/环境问题）

| 场景 | 方案 |
|---|---|
| Flask 起不来 | 直接双击 `web/dashboard_offline.html`（5.99MB 自包含，零依赖），功能完整 |

## 五、常见问题速查

| 问题 | 原因 / 解决 |
|---|---|
| 打不开 localhost:5001 | Flask 未启动。执行 `bash web/start.sh` |
| 大屏数据没更新 | 只改了数据库没重建快照。执行 `bash web/build_spa.sh` |
| Spark 报驱动找不到 | 提交时缺 `--jars` 和 `--driver-class-path` |
| Spark 连不上 MySQL | 脚本内用 `hospital-mysql:3306`（容器内网），不是宿主机 3307 |
| git push 失败 | 用 HTTP/1.1：`git -c http.version=HTTP/1.1 push origin main` |
| 医院科室都是 19 个 | 规则推导兜底，已用「含推导」标注区分，非 bug（见论文 4.3.1） |
