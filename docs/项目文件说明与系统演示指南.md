# 项目文件说明与系统演示指南

> 题目：基于Spark的北京市医疗机构资源整合与多维筛选可视化系统
> 共 **146 个入库文件**（GitHub 仓库口径；`data/`、`答辩PPT/`、`docs/images/`、论文正文、开题报告、讲解手册、`web/vendor/`、`web/dist/` 等本地留存不入库）

---


## 三、数据流转关系

```
data/*.csv (70 原始源文件)
    ↓ etl/clean_merge.py + govern_master.py + 其他治理脚本
data/processed/master_institutions.csv (9,789 家 × 42 字段)
    ↓ etl/upload_to_hdfs.py（治理后 CSV + 行为日志入湖）
HDFS /hospital/ods/raw（原始文本，唯一权威副本）
    ↓ spark/jobs/（Spark 分层 + 维度作业）
HDFS /hospital/{ods/parquet, dwd, dws/{space,category,dept,network,time}, meta}
    ↓ layer_ads.py（服务层）
MySQL hospital 库（20 张表：DWD/DWS 服务副本 + ADS 结果 + 维度表）
    ↓                                        ↓
web/build_spa.sh                        Flask /api/*（27 个 JSON 路由）
    ↓                                        ↓
web/snapshot_data.json (6.69MB)         web/vue/ 构建产物（/spa/，前后端分离）
    ↓ 注入
web/dashboard_offline.html (8.77MB) ← 零依赖兜底 / GitHub Pages 可直接访问
```

`etl/export_nlq_lexicon.py` 另外把自然语言词表从 `web/nlq.py` 导出为 `web/nlq_lexicon.json`（10.1KB），
与快照一起内联进单文件——**词表只有这一份真源**，避免两套前端各写一份词表然后慢慢漂移。

展现层有**两种形态**，共用同一份 MySQL 数据：在线形态（Vue 3，走 `/api/*`）
与单文件形态（内联快照 + 内联词表与引擎，本地解析与查询）。二者互不依赖，任一种坏掉另一种仍可演示；
**智能筛选主线两种形态都能完整跑通**（单文件形态由 `web/app.nlq.js` 本地复算，结果与后端逐字段一致）。

**改数据后的完整流程**（改一个就要全走一遍）：

```bash
# 1. 治理脚本（如改了 etl/）
python3 etl/xxx.py

# 2. 治理后数据重新入湖到 HDFS
python3 etl/upload_to_hdfs.py

# 3. 重跑数仓全链路（ODS → DWD → 六维分析 → ADS → MySQL）
bash spark/run_all.sh

# 4. 重建查询索引（overwrite 写表会清掉索引，必做）
python3 etl/create_indexes.py

# 5. 刷新自然语言词表（构建脚本会自动执行，一般无需单独跑）
#    （改了 web/nlq.py 的词表或解析逻辑后必做，否则离线版与后端会漂移）
python3 etl/export_nlq_lexicon.py

# 6. 重建单文件快照与大屏（产出 3 份 HTML，会自动内联词表与引擎）
bash web/build_spa.sh

# 7. 改了 web/vue/src/ 才需要：重建 Vue 前端
bash web/vue/build.sh

# 8. 收尾校验：产物一致性 + 双端一致性 + 冒烟 + 版面
python3 etl/verify_artifacts.py       # 三份产物 + Vue 产物一致性
python3 etl/verify_offline_nlq.py     # 前端引擎 vs 后端 NLQ，349 项断言逐字段比对
python3 etl/smoke_nlq_ui.py           # 单文件智能筛选页冒烟（45 项）
python3 etl/smoke_dashboard.py        # 单文件大屏冒烟（22 项）
python3 etl/verify_layout.py          # 响应式版面：5 档宽度 × 4 页面 + 真库页/静态 8 项，81 项

# 9. 提交
git add -A && git commit -m "..."
```

> 改动范围决定要跑几步：
> - 只改后端逻辑（不加路由）：重启 Flask 即可；若动了 `web/nlq.py` 的词表或解析逻辑，第 5、6、8 步必须跑。
> - 只改 Vue 前端（`web/vue/src/`）：只跑第 7 步；不用重启 Flask（它托管的是静态文件）。
> - 改了大屏前端（`web/dashboard.html` / `web/app.js`）：第 6、8 步。
> - 改了数据或治理脚本：第 1–9 步全走。

## 五、常见问题速查

| 问题 | 原因 / 解决 |
|---|---|
| 打不开 localhost:5001 | Flask 未启动。执行 `bash web/start.sh` |
| 大屏数据没更新 | 只改了数据库没重建快照。执行 `bash web/build_spa.sh` |
| **怎么把系统分享给别人看** | 直接发链接 **https://brooke-boom.github.io/beijing-hospital-spark/web/dashboard_offline.html** —— 零依赖单文件，智能筛选主线 + 查阅视图都能用；也可以本地双击 `web/dashboard_offline.html` |
| **单文件版点了「智能筛选」没反应 / 白屏** | 确认 `app.nlq.js`、`app.nlq.ui.js` 与内联词表已打进产物，重跑 `bash web/build_spa.sh`；白屏多半是内联脚本里的 `</script>` 未转义（构建脚本已处理，手改 HTML 时注意） |
| **离线版筛选结果和线上不一致** | 改了 `web/nlq.py` 的词表 / 解析逻辑但没重跑构建。执行 `bash web/build_spa.sh`（内含词表导出）；用 `etl/verify_offline_nlq.py` 可定位到具体用例并打出双端差异 |
| Spark 报驱动找不到 | 提交时缺 `--jars` 和 `--driver-class-path` |
| Spark 连不上 MySQL | 脚本内用 `hospital-mysql:3306`（容器内网），不是宿主机 3307 |
| 推送失败 | 本地 `.git` 对象库残缺（`bad object HEAD`），改用 Git Data API：`python3 etl/api_commit_<日期>_*.py`（先 dry-run）→ 加 `--push` |
| 医院科室都是 19 个 | 规则推导兜底，已用「含推导」标注区分，非 bug（见论文 4.3.1） |
