# 一轮真实用户试用（3—5人）

状态：待真人执行。自动化核验与作者自测均不计入真人试用。

## 人员和过程

邀请3—5位未参与开发的同学或老师，使用P01—P05匿名编号，不记录姓名、病史、联系方式。每人约15—20分钟，独立操作；主持人只读任务，不提前演示。让参与者自愿参加，可随时退出。不必实际注册或预约。开始前清空查询条件，不清空个人浏览器其他数据。记录设备、浏览器和系统快照日期，避免跨版本混用。

主持人从读完任务起计时，参与者声明完成后停止。最多180秒，超时标为失败；主持人提示或接管后完成记为“辅助完成”。无提示完成记为成功。误操作指造成错误结果或需要返回重做的操作，普通探索不计。可请求参与者边操作边说，但不要引导。

## 统一任务与判定

|编号|读给参与者的任务|主持人判定（不要提前展示）|
|---|---|---|
|T1|查出北京市全部三级医院记录，再筛选海淀区，说明两次的数量。|从全量起查，三级180，海淀区三级28；不存在智能筛选遗留子集。|
|T2|找到“医疗资源分析”，指出三级记录最多的区域，并解释该图能否证明哪个区医疗不足。|朝阳、海淀、西城各28；能指出缺少人口/床位等依据，不能直接判不足。|
|T3|查看科室来源分析，说明“有科室映射”和“有来源记录”的区别。|6745与772；知道名称/规则映射不能直接证明实际开设。|
|T4|找到一家有资料的三级医院医生，查看科室和信息来源，再打开114预约入口。|能到医生页并定位官方来源；知道覆盖未完整，预约在114完成。外站被拦截不算本站点击失败，但记录阻断，不能假装预约成功。|
|T5|查看协作网络，判断儿科44与卒中67能否直接相加得到独立机构数。|不能；交集22，两者并集89。|

每项完成后问：哪里最难找？哪里让你不确定？整轮结束问：最希望改进的一处是什么？整体操作容易程度1—5分（1很困难、5很容易）。这只是自定义单题，不能写成SUS评分。

## 记录与分析

填写“用户试用记录.csv”。每位参与者每个任务一行：状态填写success/assisted/fail；秒数为实测，误操作和帮助次数为非负整数。pending代表未执行，不可写估算值。备注记录原话或观察，区分外部114异常与本站问题。

执行分析：

```
python3 scripts/summarize_trials.py 用户试用记录.csv results/用户试用汇总.json
```

统计无辅助成功率、辅助完成率、耗时中位数、误操作和帮助次数；逐任务展示分子与分母。3—5人的便利样本只用于发现交互问题，不能代表全校或所有患者，不能进行可靠人群推广。修复后用相同任务复测，保留原始记录，并标注轮次，避免把学习效应当成优化效果。

待记录齐全后再写“试用结果”，此时不预填满意度或成功率。将填写后的CSV交给Codex，可继续归纳问题、修复并复测。
