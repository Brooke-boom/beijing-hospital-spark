# 模拟用户试用报告

日期：2026-10-21。性质：AI操作浏览器的任务走查与可用性评审，非真实用户试验。执行者已了解系统，无法模拟真正首次接触的认知过程。本轮没有招募真人，没有满意度、SUS或人类任务耗时；不计入P01—P05真人记录表。

## 环境与方法

在当前运行系统 http://127.0.0.1:5001/ 中，依据屏幕可见入口进行操作，使用当前窄屏布局与深色外观。通过实际筛选、页面切换和医生入口检查五项任务。没有调用后端接口替代前台操作，没有登录或提交预约。本轮结果为一轮模拟任务的观察，不计算真人成功率。浏览器自动化及读取等待包含工具延迟，不作为用户耗时。

## 按优先级记录的问题

### 高优先级：医生入口与资料覆盖不匹配

观察：用户从机构列表首项301医院点击“找医生”，进入待补录空结果页，必须改选其他医院才能查看资料。医院下拉已有“待补录”标注，但机构列表入口统一叫“找医生”，未提前交代。

建议：入口显示“医生资料待补录”或“查看医生收录情况”，有资料时显示“查看已收录医生”；保持全部180条可进入，不隐藏未覆盖记录。不用虚构资料填空。

### 高优先级：114外站访问阻断

观察：114标签标题为503。当前仅能确认这次环境中未正常到达预约服务，未获取外站本轮错误详情，不能断言所有用户都无法访问或断言本站链接写错。

建议：保留北京114官方入口，同时将已有“复制预约信息”作为明显的备用步骤；说明外站不可用时可稍后重试或自行通过官方渠道查询。本系统不能保证外站可用，更不能把打开链接写成预约成功。

### 中优先级：距离参考点被计入筛选条件数

观察：全量9678时显示已启用1个条件（天安门参考点）；仅选择三级后显示已启用2个条件，但“筛选依据”显示1项条件。参考点没有限定半径，却被看作减少结果的条件，两个数量口径不一致。

建议：筛选条件数仅统计改变结果集合的条件；距离参考点显示为排序/距离参考信息。若指定半径，半径才计入过滤条件。

### 中优先级：分析用语偏技术化

观察：科室说明直接出现depts、recorded_depts；“Spark预计算基准”“Jaccard”等在分析主体显示。能找到内容不代表真实用户能理解。

建议：默认用“含名称或规则推断的科室”“有公开来源支持的科室”“两个网络共同成员占比”，技术字段与计算公式放入加工记录或展开说明。

### 中优先级：区域图的默认问题与三级任务不完全匹配

观察：主图默认机构总量，最高为昌平等区；三级最多为朝阳、西城、海淀。两者数据各自正确，但新用户可能直接用主图回答三级问题。

建议：增加明确的图内指标切换或更显眼的“全部类型机构总量”标题；三级结论紧邻等级矩阵，并提示与总机构数量区别。

以上为模拟走查评审，本轮仅记录问题，未修改代码；需将整改作为独立步骤并复测，不能写成已修复。
