# 系统筛选完善记录

本轮修改以仓库提交 bbb0d7d 为基线，聚焦筛选语义、数据证据和在线离线一致性。论文未修改，远程代码库和线上页面未更新。

## 完成的修改

- 自然语言“三甲”转换为“三级甲等”组合条件，等级等次缺失的机构不计入。支持多种等级与等次组合，避免三级甲等与二级乙等交叉误匹配。
- 旧机构筛选接口支持 level=三甲 和 level_sub=甲等，并检查冲突条件。
- 旧接口及自然语言结构化条件支持 radius，范围为 0 < radius <= 200 km。半径查询只使用 coord_precision=high 的坐标，默认参考点为天安门。距离为球面直线距离，不代表路线或出行时间。
- Vue 主查询页新增等级等次、科室证据、半径、参考点设置；列表中的粗精度距离增加“约”标识。
- 科室条件支持 dept_evidence=recorded，仅使用 specialty、online、key_depts 来源，排除 name、rule 推断。来源记录不等于当前在营科室的官方确认。
- 快照构建脚本从机构科室关系表导出 recorded_depts。旧快照没有该字段时，离线引擎明确提示不支持该证据条件，不伪造补全值。
- 严格筛选返回的机构满足全部条件，因此匹配度统一为 1；并列按名称排序。移除将等级、距离和推断科室数量混为医疗质量评分的逻辑。
- 修复数据来源维度 UNION 查询重复 WHERE 占位符但未重复参数的问题；修正来源文件数被统计成“来源组合数”的问题。
- 离线查阅页科室筛选改为精确匹配 depts 映射，避免按专科文字子串误筛。
- 单文件构建脚本通过 PYTHON_BIN 或 python3 选择解释器，移除开发者个人机器绝对路径。
- Vue 构建产物、离线 HTML、Flask 模板和词表已更新；增加依赖锁文件。

## 专科数量对账结果（2026-09-17 遗留项，本机完成）

两套口径独立成立、未互通，均为真实数据但统计口径不同：

| 口径 | 机构数 | 记录数 | 来源 |
|---|---|---|---|
| 主表 `key_specialty_count`（feature L1 挂牌） | 72 家（名称归一 67） | 计数和 587 | 原始数据 feature 字段（`spark/etl_hospital.py` ADS4 注释声明） |
| 线下名单（国家级 42 + 市级 76，交 27） | 并集 92 | 513（国 230 + 市 283） | `data/processed/specialty_hospital.csv` / `specialty_municipal_hospital.csv` |

名称级比对：重叠 **58** 家；主表独有 9 家（feature 含源名单外挂牌及院区命名差异）；源名单独有 34 家（如复兴医院、平谷区医院——名单在册但主表 feature 字段无挂牌标注）。

**结论**：这是数据边界而非代码 bug。若要两口径合一，需逐家人工裁定（同名合并/院区归属/挂牌名归一），按项目铁律不擅自改数；涉及会让 72/587 变动并级联文档，留待后续治理。
